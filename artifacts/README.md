# Frankenstein 2.0 — Generated Artifacts

Owner directive, effective 2026-08-31:

Every artifact created for Frankenstein 2.0 / EntityOS work must also be persisted in this repository under `artifacts/`.

## Storage law

- `artifacts/` is the common repository landing zone for generated deliverables.
- Prefer `artifacts/YYYY-MM-DD/<workpackage-or-topic>/...` for new material.
- Preserve the original filename and format where practical.
- When an artifact is also stored in a canonical subsystem path (for example `workpackages/receipts/`, `research/`, `architecture/`, or `docs/`), keep that canonical copy there and additionally place or reference the generated deliverable under `artifacts/`.
- Artifact presence does not itself grant runtime, acceptance, effect, training, or whole-product credit. Existing evidence/authority laws remain unchanged.
- Do not place credentials, API keys, tokens, or other secrets in artifacts.

This directory exists to make all assistant/worker-produced deliverables discoverable from one stable repo location without creating a second truth authority.
