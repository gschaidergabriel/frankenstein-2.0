# P6d Preregistration — recurrent cell-state dynamics with decay

Written BEFORE any run is executed or inspected. Gabriel's directive, exact formula:

```
state(t+1)          = lambda*state(t) + alpha*uptake(t) + beta*broadcast(t) - gamma*conflict(t)
proposal_score(t+1) = signal(t+1) + kappa*f(state(t+1))     f = tanh
```

Fixed parameters for the primary run: lambda=0.7, alpha=0.4, beta=0.4, gamma=0.3, kappa=0.6.
Decay-sweep additionally runs lambda in {0.1, 0.5, 0.9} (alpha/beta/gamma/kappa held fixed).

Per-frame, per-cell definitions:
- `uptake(t)` = 1.0 if this cell is the frame's broadcast winner this round, else 0.0.
- `broadcast(t)` = winner's proposal_score if this cell is the winner, else 0.0 (only the
  winning cell's own state receives the broadcast term directly — matches "uptake" semantics:
  non-winning cells don't ingest the broadcast).
- `conflict(t)` = 1.0 if this cell is NOT the winner but its proposal_score was within 0.05 of
  the winner's (a near-miss / contested cell), else 0.0. Winner's own conflict(t) = 0.0.
- `signal(t)` = deterministic pseudo-random value in [0,1) derived from
  sha256(turn_event_id:cell:signal), identical mechanism to P6b/P6c (reproducible, not "real"
  content-derived signal — same limitation as prior rounds, noted not hidden).

Isolated persistence: new table `f2_grid10_p6d_state` (condition_key, logical_cell_id,
state_value, updated_at, updated_by_frame_id, schema), separate from P6c's
`f2_grid10_sweep_state` and from any real per-installation production state. Frames/observations
are written to the real `f2_grid10_frame`/`f2_grid10_cell_observation` tables tagged
`cohort='CONTROLLED_PROBE'`, `experiment_condition` = one of the 6 test names below, so they
remain distinguishable from ORGANIC data and from P6c's sweep. No effect on `stern.py`'s
production `_f2wp1207_grid10_frame_persist` state path.

## Six tests, run in this order, each writing its own condition_key

1. **impulse** — single strong uptake pulse into one designated cell (G3) at frame 0
   (`state(G3)` force-set to 1.0 as an experimenter-injected event, not organically won),
   then N=20 neutral frames (normal competition, no further injection). Track `state(G3)`
   per frame. **Expectation**: value jumps to ~1.0, then decays geometrically toward 0 at
   rate ~lambda per frame (allowing for organic re-winning noise).

2. **frozen** — identical stimulus sequence to a baseline run, but the state-update step
   (the `state(t+1)=...` line) is skipped every frame; `state` stays at whatever it was
   when the run started (0.0 for all cells, i.e. no history ever accumulates).
   **Expectation**: no correlation between "which cell won last round" and "which cell wins
   this round" — winner sequence should look like the frozen (memoryless) baseline.

3. **shuffle** — same dynamics as baseline, but after each update the ten state values are
   randomly reassigned across cells (values persist, cell-to-value mapping does not).
   **Expectation**: any winner-repeat structure driven by "this cell's own history" should
   collapse, because the value a cell sees next frame is no longer its own history.

4. **reset** — baseline dynamics for 15 frames, then all ten states are hard-reset to 0.0,
   then 15 more frames. **Expectation**: any repeat-win/impulse-style effect measurable in
   the first 15 frames should not carry across the reset point (frame 16 conditioned on
   frame 15 should look like frame 1 conditioned on nothing).

5. **decay_sweep** — baseline dynamics rerun at lambda in {0.1, 0.5, 0.9} (alpha/beta/gamma/
   kappa fixed at primary values), N=20 frames each. **Expectation**: measured effect size
   (repeat-win rate above the ~10% chance floor, or impulse half-life) increases monotonically
   with lambda.

6. **counterfactual** — two parallel runs (`cf_a`, `cf_b`) sharing identical stimulus seeds
   for frames 11-15, but diverging prior history for frames 1-10 (cf_a: G5 gets 3 injected
   uptake pulses in frames 1-10; cf_b: no injections, organic only). **Expectation**: for the
   IDENTICAL frames 11-15 stimuli, proposal_score(G5) and/or winner distribution differs
   between cf_a and cf_b.

All six tests use `n_epochs=2` real RuntimeEpochs (via `stern._f2wp1207_runtime_epoch`,
`force_new=True` for the second epoch — same mechanism P6c used, no live process kill
required for this offline dynamics test) to confirm state persistence survives an epoch
boundary as well as within-epoch frames.

## PASS criteria — ALL required, fixed here, not adjusted after seeing results

- (A) History changes the later proposal/selection distribution at IDENTICAL current stimulus
  (shown by test 6, counterfactual divergence).
- (B) Frozen-state (test 2) reduces/eliminates the repeat-win effect relative to baseline.
- (C) Shuffle (test 3) reduces/eliminates the repeat-win effect relative to baseline.
- (D) Reset (test 4) eliminates carry-over of the effect across the reset boundary.
- (E) Impulse-response (test 1) shows a decaying — not flat, not immediately-zero — influence
  curve.
- (F) Effect size tracks the decay parameter monotonically (test 5).

**PASS** = all six criteria hold. **FAIL** = any control (B/C/D) does NOT collapse the effect,
or (E)/(F) do not show the expected shape → conclusion is "state persists mechanically but is
not yet shown causally load-bearing in the current proposal/competition coupling" — documented
honestly, no further data collection, the coupling itself needs rework, not the sample size.
